# northsite

One static page. Thirteen sites that are live right now, where a shop would put its stock, and a
booking sheet where a shop would put its cart.

**Booking:** https://calendly.com/charlesmuwangam/intro-call

northsite is the web build arm of Visuals by Fiets. Same person, same shop, which is why the
wordmark carries "by visualsbyfiets" beside it.

## The idea

The `noorperfumes-shop` build has a persistent bottom bar that raises a full sheet holding the
cart. Here the same bar, in the same position, with the same `cubic-bezier(.32,.72,0,1)` over the
same 280ms, raises a sheet holding a real Calendly widget instead. Someone who has just watched
four sites open in four new tabs reaches for the gesture a shopper reaches for when they are ready
to buy, and the next step is already sitting there.

Each card opens the real deployment in a new tab. Where a product card would print a price, these
print a verified fact instead: 149 dishes, 7 doctors, 19 routes, 10M+ views.

## The logo as a system

The mark is a browser window holding two chevrons and a cursor. All three parts are used
separately, so the page is built out of its own logo rather than decorated with one:

- **The three dots** from the title bar mark every section, and sit on the slim bar above every
  card. That bar is why each card reads as a window.
- **The chevrons** bracket each section number.
- **The cursor** is every "this opens something" affordance: the Open link on each card, the header
  link, the booking fallback. On a fine pointer it also becomes the hover label, so moving over a
  card produces the logo's own arrow carrying the words "Open the real site".

The one accent colour is the blue sampled straight out of the mark. It appears on the scroll
progress line, the word "live" in the headline, the card index numerals, the section chevrons, the
benefit numerals, the zero in the stock readout, and every hover state. Nowhere else.

## Local

```bash
npm install
npm run shoot     # capture every shelf screenshot from the live sites
npm run build     # encode images, generate the page, write dist/
npm run cards     # social card, touch icon, Awwwards thumbnails (needs the dev server up)
npm run dev       # serve dist/ on http://localhost:4220 with gzip and cache headers
```

The dev server gzips and sets cache headers deliberately. Without it a local Lighthouse run is
penalised for 111 KiB of compression GitHub Pages applies anyway, and the score means nothing.

## Verifying

```bash
npm run verify    # check + a11y + pin + qa
npm run check     # gates: em dash, banned phrasing, every link, no-JS, reduced motion, the sheet
npm run a11y      # axe-core at 1440 and 390, sheet closed and open
npm run pin       # proves the featured image holds through the last step
npm run qa        # full-page captures at 10 widths, reports overflow and gutters
npm run vitals    # real LCP/CLS/long-task/frame-time at 1.6 Mbps, 150ms RTT, 4x CPU
npm run proof     # interaction shots: hover cursor, sheet open, pin mid-hold
npm run contrast  # prints the measured ratio for every text tone in the palette
```

`npm run check` exits non-zero on any failure, including a shelf link that stops answering. That is
the claim the hero makes about itself, so it is enforced rather than asserted.

## Adding a project to the shelf

Everything the shelf renders comes from [`src/data/projects.json`](src/data/projects.json). Move an
item from `held` to `cleared`, give it the fields the others have, then:

```bash
npm run shoot && npm run build && npm run check
```

The stock count in the hero, the JSON-LD, the section copy and the Awwwards thumbnails all read
from that one file. A card can set `shotUrl` to capture a different page from the one it links to.

## Stack

Plain HTML, CSS and JavaScript, generated by a Node script. No framework and no CMS, because one
page needs neither.

- **Type:** Switzer 400 and 700, self-hosted, official WOFF2 unmodified
- **Motion:** GSAP, ScrollTrigger, SplitText and Lenis, all self-hosted
- **Images:** ffmpeg, Lanczos downscale to WebP q80
- **Booking:** Calendly in an iframe, with a styled link as the fallback

Nothing loads from a third-party CDN, so no CDN sees a visitor's IP and there is nothing about one
to disclose. Calendly is the only outside request on the page and it is not made until someone
opens the sheet.

The 142 KB motion stack is fetched after first paint rather than during it. Parsed during load on a
throttled phone it pushed modelled LCP from 1.1s to 1.8s. Nothing above the fold depends on it, and
if it never arrives the `html` element keeps its `no-js` class and the page stays fully readable.

### Why Switzer and not Helvetica

The build was specified in Helvetica and two Helvetica TTFs were supplied. Their embedded metadata
reads `(c) 1990-2006 Apple Computer Inc. (c) 1981 Linotype AG`, version `10.0d4e1`: Apple's macOS
system Helvetica, redistributed by a font-download site with no license file. Self-hosting that as
a WOFF2 means redistributing Apple's font binary.

Nimbus Sans was the first replacement considered and then rejected. The URW release is **AGPL v3**,
and its only exception covers embedding in a PostScript or PDF document, not serving as a webfont.

Switzer is a Swiss grotesque in the same lineage, and the ITF Free Font License it ships under
permits self-hosted `@font-face` for commercial use in as many words. It also forbids subsetting
and format conversion, so the official WOFF2 files ship byte for byte. Two weights cost 37 KB,
small enough that subsetting would not have been worth it. The license travels with the fonts at
[`assets/fonts/Switzer-FFL-LICENSE.txt`](assets/fonts/Switzer-FFL-LICENSE.txt).

Swapping the typeface is one `@font-face` pair and one `font-family` in
[`src/styles.css`](src/styles.css) if a real Helvetica web license is ever bought.

### Why secondary text is a colour and not an opacity

Ink at 45% to 55% over paper measures 2.96 to 4.03 against a 4.50 contrast floor, which is how the
hero manifest failed axe on the first pass. `--ink-2` and `--ink-3` are solid tones measuring 10.10
and 5.08. `npm run contrast` prints every ratio in the palette, including the two that have to
clear the floor against both the navy bar and its blue hover state.

## Deploy

GitHub Pages, served from the `gh-pages` branch, which holds the contents of `dist/` and nothing else. `npm run deploy` builds and force-pushes it. Asset
paths are all relative, so the site works at a repository subpath without a base-path variable.
`NS_BASE` only sets the canonical URL, the `og:url` and the sitemap.
